# 软总线 / 解析桥 / 代理桥 —— 协议对齐说明

> 适用：FnReader 服务端 **2.6.17 / 2.6.18**（软总线路由权重、领取锁、结果幂等、媒体类任务）。
> 更早的 2.6.x 协议是本节的真子集，字段向后兼容。

本文是 FnReader-TRE（路由器解析引擎）与 FnReader 服务端、手机端对齐的协议依据。
所有结论来自本地仓库真实代码与文档，不引入推测字段。

参考位置：

- 服务端：`FnReader/legado-web/app/server/src/server.js`、`remote.js`、`ebook/bus.js`、
  `ebook/local.js`、`ebook/epub.js`、`ebook/html.js`、`ebook/pdf.js`、`ebook/text.js`
- 手机端：`yuedu-pro/app/src/main/java/io/legado/app/model/FnReaderEbook.kt`、
  `FnReaderBridgeService`
- 规范文档：`FnReader/docs/电子书解析引擎接入.md`、`Text-Parsing-Engine/docs/AI-INTEGRATION.md`

## 1. 三条链路的分工

```
┌────────────┐   建任务 POST /api/remote/job    ┌──────────────┐
│  管理端/书库 │ ───────────────────────────────> │  legado-web  │
└────────────┘                                  │  软总线调度   │
                                                └──────┬───────┘
                                     pending 长轮询     │ 派单
                        ┌──────────────────────────────┴───────────────┐
                        │                                              │
                  ┌─────▼─────┐                                 ┌──────▼──────┐
                  │ 手机 App  │  ebookMode=proxy 时优先         │  路由器 TRE  │
                  │ 解析桥     │                                 │  解析桥节点  │
                  └─────┬─────┘                                 └──────┬──────┘
                        │  part 分片上传 / result                      │
                        └──────────────► 服务端 ◄─────────────────────┘
                                           │
                                    超时/离线/掉线
                                           ▼
                                    服务端本机兜底（local）
```

- **软总线（remote bus）**：任务队列 + 设备心跳 + 结果回传。服务端是唯一调度者。
- **解析桥**：真正干活的节点（手机或路由器），负责下载、解析、分片上传。
- **代理桥（proxy）**：`ebookMode=proxy` 的调度策略——有在线设备就派给设备，
  设备超时/离线/掉线时服务端本机接手，保证任务一定完成。

路由器 TRE 只实现「解析桥 + 软总线客户端」，不修改服务端调度策略。

## 2. 软总线协议

### 2.1 领任务 / 心跳

```
GET /api/m/remote/pending?id=<deviceId>&name=<deviceName>&model=<model>&ver=<ver>&wait=<sec>&limit=<n>
Header: X-Api-Token: <token>
```

- `wait` 为长轮询秒数，服务端默认 10 s、上限 30 s；TRE 默认 20 s。
- TRE 0.3 起写死 `limit=1`、单线程领取：每次只锁 1 个任务，处理完再领下一个。
- 每次 pending 同时完成心跳：服务端 60 s 内没收到心跳即判设备离线。
- 返回：

```json
{ "jobs": [ { "id": "job-xxx", "type": "ebook-parse", "taskClass": "content", "payload": { }, "age": 1234 } ], "waitMs": 20000 }
```

- 服务端在 `/api/setup` 未确认缓存位置时，pending 返回 **409 `needConfirm`**；
  TRE 把它当普通错误退避重试，等待管理员先在网页端确认。
- 服务端会把未完成任务重复下发；TRE 按 `job.id` 去重，同一 `sha1` 的整本任务
  同时只跑一个，队列满时直接丢给服务端重派（不 ack、不阻塞轮询）。

### 2.2 回结果

```
POST /api/m/remote/result
{ "id": "<jobId>", "ok": true, "data": { ... }, "deviceId": "<deviceId>" }
{ "id": "<jobId>", "ok": false, "error": "drm", "deviceId": "<deviceId>" }
```

- 服务端 `remote.js` 对已回收/已兜底的任务返回 `accepted:false`；
  2.6.17+ 结果幂等后还可能返回 `{ "ok": "duplicate" }`（重复回传）、
  `{ "ok": "stale" }`（非锁定设备）、`{ "ok": true, "accepted": false, "ignored": true }`
  （调试设备）；TRE 把这些都视为终态，不重试、不重复扣分。
- `data` 对 `ebook-parse` 为 `{chapters, parts, chars}`（`parts` 明确为**含 part0 的总片数**）；
  对 `ebook-chapter` 为 `{title, paragraphs}`；媒体类任务见 3.4。

### 2.4 任务分类、隐藏分与领取锁（2.6.17/18）

- 任务类：`book`（`search`/`toc`/`rank`）、`content`（`content`/`ebook-parse`/`ebook-chapter`）、
  `media`（`cover`/`intro`/`bookinfo`）。
- 每台设备在服务端维护隐藏分：初始 50，成功 +4，失败 −8，成功但耗时 >8 s 再 −2，范围 0–100；
  `>=55` 为高分，可领全部类、在途上限 3；`<55` 只领 `media`，在途上限 2。
- 在线高分设备为 0 时自动放开全部类；调试设备不限类但回传一律丢弃。
- `pending` 领取即锁 30 s，锁过期可被其它设备重领；`pending` 按实际锁定任务重算在途数
  （2.6.18 修复泄漏），只返回剩余名额内任务。
- 设备超过 60 s 无心跳视为离线；`enabled=false` 时 `pending` 直接返回空数组。
- TRE 不伪造分数、不声明调试设备：分数完全由服务端按回传结果计算。
- TRE 0.3 的领取策略（写死，见 README）：
  - 只领 `media` 类（`cover`/`intro`/`bookinfo`）；服务端误派 `book`/`content` 时，
    立即回传 `{ok:false, error:"unsupported"}`，服务端按失败 −8 分并自行兜底；
  - 单线程 + `limit=1` 控制成功加分频率；
  - 两者叠加使设备分数无法稳定维持在 `>=55`（高分档），等效「隐藏分封顶 50」。
    注意：协议没有字段能让客户端直接写服务端隐藏分，此为实现等效效果，不是真写死。

### 2.3 任务 TTL

- 服务端 `remote.create(type, payload, {waitMs, ttlMs})`；
- `ebook-parse` 单独放宽到 **600 s**；
- 服务端兜底 `ebookFallbackAfterMin` 默认 10 min；看门狗 `ebookOfflineGraceSec`
  默认 120 s，无新分片就 `remote.abandon` 本地接手；
- TRE 自身超时：整本 12 min、单章 3 min，超时回 `timeout`。

## 3. 解析桥协议（fnreader.ebook.v1）

### 3.1 下载原书

```
GET /api/m/ebook/file/<sha1>
Header: X-Api-Token: <token>
Range: bytes=<have>-
```

- 支持 Range 续传；TRE 下载后校验 sha1，不一致删掉重下一次，仍不一致回 `corrupt`。

### 3.2 分片上传

```
POST /api/m/ebook/part?sha1=<sha1>&seq=<n>&total=<N>
Content-Type: application/json
Content-Encoding: gzip        # 明文 > 64 KB 时启用
```

- `seq=0` 是**清单**（part0）：

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "…",
  "format": "epub",
  "name": "书名",
  "meta": { "title": "…", "author": "…", "language": "…" },
  "toc": [ { "id": "ch0001", "title": "第一章", "level": 1, "index": 0 } ],
  "stats": { "chapters": 3, "chars": 102, "parts": 4 }
}
```

- `seq>=1` 是正文片：

```json
{
  "schema": "fnreader.ebook.v1",
  "sha1": "…",
  "seq": 1,
  "total": 4,
  "chapters": [
    { "index": 0, "id": "ch0001", "title": "第一章",
      "paragraphs": [ { "k": "p", "t": "正文" }, { "k": "h1", "t": "小标题" } ] }
  ]
}
```

硬约束：

| 项 | 规则 |
| --- | --- |
| `k` | 只允许 `p` / `h1`~`h6` / `quote` / `hr` / `img` |
| `index` | 全书从 0 连续，不跳号 |
| `total` | `1 + 正文片数`，上限 10000 |
| 单章数 | 每片 ≤ 50 章（协议允许 200），TRE 按 50 章或 2 MB 切，不拆章 |
| 体积 | 单请求明文 ≤ 8 MB，解压后 ≤ 20 MB |
| toc | ≤ 3000 章；`tocOnly:true && total===1` 才是 toc-only |

服务端细节：

- part0 已存在 `book.json` + 分片时重传返回 **409 `toc-locked`**，TRE 当作已完成跳过；
- 正文片重复上传服务端按幂等处理；TRE 先查 `/api/m/ebook/parts` 跳过已收分片；
- 服务端对上传文件做 mtime 20 s 保护并 chmod 644。

### 3.3 断点与单章

```
GET  /api/m/ebook/parts?sha1=<sha1>     -> { total, received:[seq...], complete, status }
GET  /api/m/ebook/chapter?sha1=<sha1>&index=<n>   # 单章补章（服务端按需）
POST /api/m/ebook/chapter?sha1&index    # 单章回传（可选）
```

- `ebook-chapter` 任务也可以走 `POST /api/m/remote/result` 回
  `{title, paragraphs}`，TRE 采用这种方式，避免额外写库路径。
- TRE 解析结果落 `parsed/<sha1>.json.gz`，单章补章命中缓存时毫秒级返回。

### 3.4 媒体类任务（2.6.17+）

| 类型 | payload | 回传 `data` | 取不到时 |
| --- | --- | --- | --- |
| `cover` | `{bookUrl, source, name, author}` | `{coverUrl}` | 回 `ok:false` + `not-found`，服务端回退 `bookinfo` |
| `intro` | 同上 | `{intro, author, kind, wordCount, lastChapter, totalChapterNum}`（后几项可省略） | 同上 |
| `bookinfo` | 同上 | 同 `intro` + `coverUrl` | 服务端本机抓取兜底 |

TRE 的实现（0.3 起）分两层：

1. **书源规则优先**：payload 的 `source`（bookSourceUrl）命中服务端 `/api/m/sources.json`
   （本地缓存 10 分钟）时，用该源 `ruleBookInfo` 解析详情页；`init` 能换算成 http(s)
   地址时按其抓取，否则用 `bookUrl`。
2. **通用解析兜底**：规则不命中或字段为空时，读 `og:*` / `meta` / JSON-LD / 封面 `img` /
   简介区块，只补空字段、不覆盖规则结果。

书源规则子集（`engine/parse/rulex.go`）：`||` 多段依次尝试；`@` 分步（`class.`/`id.`/`tag.`/
`@css:` 选择器 → `text`/`textNodes`/`ownText`/`all`/`html` 或属性名取值 → 可选 `##正则##`，
连续两个 `##` 为替换形式）；`{{bookUrl}}`、`{{name}}`、`{{author}}` 占位替换。
`@js:`/`@json:`/`@put:`/`@get:` 等表达式类规则整段放弃，自动回退通用解析。
相对封面地址按最终页面 URL 补全；页面取不到回 `fetch`。
JS 动态渲染、需要登录或反爬的页面可能取不到，按失败回传由服务端兜底。

## 4. 代理桥（ebookMode）

| 模式 | 行为 |
| --- | --- |
| `proxy`（默认） | 有在线设备就派 `ebook-parse`；等待 240/600 s，超时/离线/掉线由服务端本机兜底 |
| `local` | 不派设备，服务端本机解析 |
| `off` | 关闭电子书解析 |

TRE 的定位：

- 只领取服务端派下来的任务，**不主动建任务、不改 ebookMode**；
- 设备离线不会导致任务失败：服务端看门狗 120 s 无新分片即本地接手；
- 因此 TRE 允许任务失败（回 `timeout`/`io`），服务端兜底逻辑保持原样。

## 5. 错误码

| code | 触发 | 服务端行为 |
| --- | --- | --- |
| `drm` | EPUB `encryption.xml` / MOBI 加密标志 | 直接 failed，不兜底 |
| `corrupt` | zip/记录表/sha1 校验失败 | 直接 failed |
| `unsupported` | 非 EPUB/MOBI/PDF/TXT 或压缩方式不支持 | 直接 failed |
| `kf8-unsupported` | MOBI version ≥ 8（AZW3/KF8） | 直接 failed |
| `no-text-layer` | PDF 无可抽取文本 | 直接 failed |
| `font-encoding` | PDF CID 字体缺 ToUnicode，乱码 | 直接 failed |
| `schema` | payload schema 不匹配 | 直接 failed |
| `index` | 单章 index 越界 | 直接 failed |
| `too-large` | 章节数 > 3000 | 直接 failed |
| `timeout` / `io` / `download` / `upload` | 网络、磁盘、服务端 5xx | 服务端本地兜底 |

TRE 映射：`parse.Error.Code` 原样上送；`context.DeadlineExceeded` → `timeout`；
下载/404 → `download`；上传失败 → `upload`；其余 → `io`。

## 6. HTML → k/t 规则（与服务端一致）

- 跳过 `script/style/noscript/head/svg` 子树；
- `h1`~`h6` → `k=hN`；`blockquote` → `quote`；`hr` → `hr`；`img` → `img`（`alt/title` 作文本）；
- 其余块级（`p/div/section/article/li/td/pre/...`）→ `p`；
- 行内标签只取文本；`<br>` 断段；
- 空白折叠、实体解码；单段超过 4096 字符按句切分；
- 首段若与章节标题相同则丢弃（`dropTitle`）。

## 7. 配置映射（UCI → 引擎）

| UCI | 默认 | 用途 |
| --- | --- | --- |
| `enabled` | 1 | 是否启动 |
| `server` | `http://192.168.5.110:1122` | 服务端基址，自动补 `http://`、去尾 `/` |
| `token` | 空 | `X-Api-Token` |
| `device_name` | 空 | pending 的 `name` |
| `cache_dir` | 空 | 缓存根；空且自动检测时选 USB |
| `usb_autodetect` | 1 | 扫 `/mnt/*` |
| ~~`concurrency`~~ | 已废弃 | 0.3 起引擎写死单线程，安装脚本会删除该项 |
| `poll_wait` | 20 | pending wait（0-30） |
| `part_max_mb` | 2 | 正文分片字节上限（1-8） |
| `cache_max_mb` | 2048 | 缓存上限，0 不限 |
| `tmp_ttl_hours` | 48 | 原文件保留 |
| `log_level` | info | 日志级别 |
| `claim_types` | `cover,intro,bookinfo`（写死） | 引擎忽略 UCI 取值，只承接媒体类 |

## 8. 设备标识

- 优先 `/etc/machine-id`，其次第一块非 loopback 网卡 MAC；
- `sha1("fnparse:"+seed)` 取前 10 位 hex，形如 `owrt-3f2a1b9c8d`；
- 都拿不到时在缓存目录写 `device.id`（随机 6 字节 hex），重启保持稳定；
- `model` 固定 `openwrt`，`ver` 为引擎版本（0.3）。

## 9. 时序（整本解析）

```
服务端                          路由器 TRE
  │  pending(hold 20s)              │
  │───────────────────────────────>│
  │  jobs=[ebook-parse sha1=A]      │
  │<───────────────────────────────│
  │                                 │ 查 parsed/A 缓存（有则跳过解析）
  │  GET /ebook/parts?sha1=A        │
  │<───────────────────────────────│
  │  GET /ebook/file/A (Range)      │
  │───────────────────────────────>│
  │                                 │ sha1 校验 → 解析 → 构造 part0..N
  │  POST /ebook/part seq=0         │
  │<───────────────────────────────│
  │  POST /ebook/part seq=1..N      │
  │<───────────────────────────────│
  │  POST /remote/result ok         │
  │<───────────────────────────────│
  │  服务端落库，任务完成             │
```

若中途掉线：服务端 120 s 无新分片 → `remote.abandon` → 本机兜底；
TRE 重连后同一 sha1 已有解析缓存，直接续传剩余分片。
